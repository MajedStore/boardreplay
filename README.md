# BoardReplay

**Turn whiteboard photos into replayable lessons.**

BoardReplay is a local, single-user educational workspace. Arrange classroom photographs chronologically, reconstruct their captured content through a configured vision provider, inspect the source evidence, replay the steps, correct the notes, and export through the browser's PDF print flow.

The bundled synthetic lesson works without credentials. It is explicitly labeled **SAMPLE DATA** and was not generated by a live provider. BoardReplay cannot recover writing that was erased before any photograph captured it.

## Local setup

Use Node.js 24 LTS and npm. Development was validated with Node **24.15.0**. SQLite and uploads require a writable local filesystem.

From the project directory, run:

```powershell
npm install
Copy-Item .env.example .env
npm run db:generate
npm run db:migrate
npm run demo:frames
npm run dev
```

On macOS/Linux replace `Copy-Item .env.example .env` with `cp .env.example .env`.

Open **http://127.0.0.1:3000**. The application intentionally binds to the loopback interface. No account registration is required. `demo:frames` regenerates the original programmatically drawn sample fixtures; it does not call an image-generation API.

The development script uses Next.js's supported Webpack mode. In this Windows workspace, Turbopack's filesystem tracking repeatedly refreshed pages when local SQLite/upload files changed; Webpack keeps the development UI stable. Production builds still use the default Next.js build engine.

The checked-in migration creates the SQLite schema. `npm run db:dev -- --name your_change` creates a migration when changing the data model. Commit migration files with schema changes.

After dependencies and database setup:

```powershell
npm run test
npm run typecheck
npm run lint
npm run build
npm run start
```

Run browser tests with:

```powershell
npx playwright install chromium
npm run test:e2e
```

Playwright browser installation may need network access and available system dependencies. The browser test configuration starts its own application server when needed. Automated provider tests mock network responses; they do not spend API credits.

## Provider configuration

Put credentials in the project's **`.env` file on the server**. Restart the development or production server after changing them. Never use `NEXT_PUBLIC_` for secrets, paste credentials into lesson instructions, or commit `.env`.

| Provider         | Server key          | Configurable model | Default             |
| ---------------- | ------------------- | ------------------ | ------------------- |
| OpenAI           | `OPENAI_API_KEY`    | `OPENAI_MODEL`     | `gpt-5.4-mini`      |
| Google Gemini    | `GOOGLE_API_KEY`    | `GEMINI_MODEL`     | `gemini-3.6-flash`  |
| Anthropic Claude | `ANTHROPIC_API_KEY` | `ANTHROPIC_MODEL`  | `claude-sonnet-4-6` |

All three adapters use their official TypeScript SDKs. A configured, accessible vision model can run the complete extraction and reconstruction workflow. The UI reports whether each key is present; this is a configuration indicator, not proof that the key has working billing, quota, or model access. Actual provider responses record the returned model identifier when available.

OpenAI uses the **Responses API**, image data URLs, strict `text.format` structured output, and `store: false`. Gemini uses inline image data and a JSON response schema through `@google/genai`. Claude uses base64 image blocks and generally available `output_config.format` JSON output. A custom model must support images and the structured-output convention used by its adapter.

Each SDK request has a 90-second timeout. The application retries transient failures at most twice after the initial request, with bounded exponential backoff. SDK-level retries are disabled to keep the total bounded. Authentication, invalid output, and missing configuration fail explicitly. A failure never produces substitute sample notes for an uploaded lesson.

Current official implementation references:

- [OpenAI Responses structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)
- [OpenAI image inputs](https://developers.openai.com/api/docs/guides/images-vision?api-mode=responses)
- [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)
- [Gemini structured outputs](https://ai.google.dev/gemini-api/docs/generate-content/structured-output)
- [Gemini image understanding](https://ai.google.dev/gemini-api/docs/image-understanding)
- [Gemini 3.6 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.6-flash)
- [Claude structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
- [Claude vision](https://platform.claude.com/docs/en/build-with-claude/vision)

Models and account access can change. Override the documented defaults if your provider account uses a different supported model. API use is billed by the provider. No live provider response was used as a substitute for a mocked test.

## First walkthrough

1. Choose **Explore demo** to create a sample lesson with sequential board photographs and prebuilt, labeled notes. Use this to try the source viewer and replay without a key.
2. Create a real lesson and enter a name, course, optional topic/date/language, and reconstruction instructions.
3. Upload JPG/JPEG, PNG, or WebP images. Drag files into the upload area, choose multiple files, or use mobile camera capture. Review the thumbnails, rotate images as necessary, and place them in lecture order.
4. Select a configured provider and start reconstruction. The lesson shows actual **EXTRACTING**, **RECONSTRUCTING**, **COMPLETED**, or **FAILED** states; stage labels are not measured progress percentages.
5. Select a reconstructed step to inspect its cited original photographs, original transcription, evidence status, and uncertainty. Compare difficult equations against the source.
6. Replay with play/pause, previous/next, restart, speed, seek, and keyboard controls. Previously revealed steps stay visible.
7. Correct text or LaTeX, adjust sections and order, and save. User corrections are labeled **USER_EDITED**. Previous reconstructions are saved as revisions when editing or rerunning, so earlier work can be restored.
8. Open the print view, choose whether to include source photographs and uncertainty notes, and use **Print / Save as PDF**. Wait for equations and images to finish loading before saving.

The replay follows the reconstructed captured sequence. It does not claim to reproduce the professor's exact writing movements, speech, or timing.

## Upload and storage behavior

- Maximum **20 images per lesson**, **10 MB per image**, and **100 MB per upload request**.
- JPG, PNG, and WebP only. The server checks declared MIME type, decoded image format, corruption, dimensions, and single-frame content. Empty files and images smaller than 40 × 40 pixels are rejected. Decoding is bounded to 40 million pixels.
- Original bytes are preserved in `UPLOAD_DIR`, with generated storage filenames. User filenames never determine filesystem paths.
- Metadata records filename, image ID, lesson, ordering, dimensions, MIME type, upload time, and rotation. Reordering after reconstruction marks the lesson for reprocessing.
- Provider inputs are JPEG copies, automatically oriented, rotated as reviewed, and fitted within 2200 × 2200 pixels. Original files remain available for higher-resolution inspection. Small handwriting may therefore require closer photographs.
- Deleting a lesson cascades through its database records and removes its stored image files. Deletion is permanent; keep a backup if you need one.

The default configuration uses `DATABASE_URL="file:./data/boardreplay.db"` and `UPLOAD_DIR="./data/uploads"`. Keep the database and uploaded files together when backing up or moving a workspace. Retained original files may include metadata from the camera.

## Evidence and mathematical reliability

Every reconstructed block has a unique ID, type, section, chronological step index, source image IDs, and evidence status:

| Status        | Meaning                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------ |
| `OBSERVED`    | Reported as directly visible in a supplied photograph. Check the source to verify transcription. |
| `DERIVED`     | An inference, translation, or optional educational explanation derived from visible evidence.    |
| `UNCERTAIN`   | Unreadable, ambiguous, incomplete, conflicting, or missing a source citation.                    |
| `USER_EDITED` | Manually corrected or supplied material.                                                         |

Structured-output validation checks shape and citation integrity. Unknown source image IDs and duplicate step IDs are rejected. Uncited automatic content is downgraded to uncertain. These checks cannot prove that an AI transcribed the actual cited pixels correctly. Citations enable human inspection.

Prompts require preservation of earlier captured content and both versions of a correction. Exact overlaps can be merged with their supporting references. Separate problems must remain separate, and uncertain missing work must stay explicit. No source regions or bounding boxes are invented.

The independent verifier handles a small set of complete **numeric equalities**: decimal numbers, parentheses, `+`, `-`, multiplication, division, bounded powers, and simple LaTeX fractions. It uses a restricted parser, never `eval`. It marks mismatching numeric sides suspicious. Symbolic algebra, diagrams, proofs, multiline derivations, and unsupported expressions are **not independently verified**. A verified numeric equality does not prove an entire derivation. KaTeX renders mathematics with HTML trust disabled; Markdown does not execute raw HTML.

The KaTeX dependency is kept on the same compatible 0.16 release line used by `rehype-katex`, so the renderer and its CSS agree on equation layout (including fractions, radicals, and boxed results).

## AI Comparison Lab and academic report

Create a comparison from a saved lesson. Its prompt and ordered image snapshot are saved so each tool sees equivalent instructions and the same original image IDs, sequence, and rotation. If a snapshot image is deleted, create a new comparison.

**Automatic mode** sends the common prompt and images through a configured provider. It stores the actual raw output, returned model, timestamp, and measured elapsed time. It does not fabricate a score.

**Manual mode** stores text pasted from the official ChatGPT, Gemini, or Claude interface. Enter the model identifier if known. These entries remain labeled manual; no API timing is fabricated. Expand **View frozen prompt & image order**, download every **prepared photo**, attach those JPEGs in the listed order, and use **Copy prompt**. The prepared downloads are the exact `imageForAI` bytes used by automatic mode, with the saved snapshot rotation, automatic orientation, 2200-pixel bound, and JPEG quality 90. Later changes to the lesson’s order or rotation do not alter them. Copy prompt includes the full API evidence instructions, common saved prompt, and identical ordered source-image labels/IDs; do not substitute current/original files or copy only the common prompt.

The shared instructions and source-label wrapper are versioned as `boardreplay-benchmark-v1` in `lib/benchmark.ts`; they contain no secrets. Start a new benchmark if this static wrapper changes between application versions. CSV/JSON exports include the equivalent full manual prompt and wrapper version. Official interfaces may impose their own hidden instructions, preprocessing, and generation settings, so equivalent supplied instructions and bytes do not guarantee identical model behavior. Report thumbnails for a selected benchmark also use its prepared snapshot images.

Assess each output from 0–5 across eight categories: text accuracy, equation transcription, chronology, preservation of earlier erased content, deduplication, detection of missing information, hallucination avoidance, and readability. Scores, strengths, weaknesses, and rankings are based on **human assessments**. Rankings appear only when at least two distinct providers have complete assessments for the common benchmark; repeated results from one provider do not count as different tools. An optional verified reference supports exact text agreement and word edit/error metrics. Text similarity does not establish semantic or mathematical correctness, and another model's agreement is not proof.

Export comparison results to JSON or CSV. CSV output escapes spreadsheet formula prefixes. The academic report editor combines saved project narrative, real comparisons, actual outputs, reference metrics, limitations, and user conclusions in a print-friendly document. Its length depends on the selected data and written content; adjust the browser print settings for an approximately 3–5 page submission. No experiments, findings, scores, or conclusions are invented for the report.

## Architecture

```text
app/                         Next.js App Router pages and server API routes
components/                  Shared UI, source board, replay, comparison, and layout
lib/ai/                      Official SDK adapters, strict wire schemas, prompts, pipeline
lib/reconstruction/          Citation validation, ordering, numeric equality verification
lib/storage/                 Image inspection, original file storage, provider JPEG inputs
lib/validation/              Shared request and reconstruction Zod schemas
lib/comparison.ts            Human scoring, ranking, text reference metrics, CSV export
lib/lessons.ts               Database serialization and lesson services
lib/db.ts                    Prisma client with local SQLite adapter
lib/types.ts                 Shared application contracts
prisma/                      Relational schema and checked-in SQLite migration
public/demo/                 Original synthetic board frame fixtures
scripts/generate-demo.mjs     Programmatic sample image generation
tests/                       Mocked unit/integration tests and browser journeys
```

The main pipeline is:

```text
Ordered original images
  → validated and normalized provider JPEG copies
  → schema-validated observations per photograph
  → chronological lesson reconstruction from ordered observations
  → source-reference validation and limited numeric checks
  → persisted notes + extraction records + processing run
  → source inspection, human edits, replay, and print export
```

The primary data model stores lessons, ordered lecture images, processing runs, per-image extractions, reconstruction revisions, comparisons, provider results with assessment scores, and report drafts. Sections and steps are structured JSON within a lesson/revision. Relational children use cascading lesson deletion. SQLite persistence is on the Node.js server, not browser localStorage; localStorage holds only interface preferences such as the selected theme.

Processing uses a Next.js Node.js route and `after()` background work, with persisted stage transitions polled by the workspace. A database update prevents simultaneous reconstruction claims. A global in-process registry keeps active uploads/reconstructions protected across development module reloads and blocks source edits while benchmarks are reading photographs. A persisted busy operation with no live task after a server restart is marked failed when the lesson is next accessed, allowing a retry. Comparisons also have a local process lock per provider/run. The interface does not stream fabricated progress percentages.

## Security, privacy, and deployment

This MVP is designed for one user on a trusted local computer. It validates request schemas and upload content, generates safe storage paths, rejects cross-origin mutations, bounds upload/API use, and returns fixed public provider error messages without keys, image payloads, or internal stack traces. Provider calls execute on the server. Request/image bodies and credentials are not intentionally logged by the application.

Photos and notes stay on the local server until the user starts an automatic reconstruction or benchmark. That action sends normalized photograph copies and lesson context to the selected external provider. Reconstruction sends the extracted observations in a second request. Review the selected provider's terms and data controls for your account. Manual submission only stores the text you paste locally.

For a production build on a persistent machine:

```powershell
npm install
npm run db:generate
npm run db:migrate
npm run build
npm run start
```

Keep `.env`, the SQLite file, and the upload directory on persistent storage with appropriate OS permissions and backups. The migration command must run against the same database used by the application. Fresh-database migration was checked with the project-root database path; the Prisma configuration resolves the URL and creates an empty SQLite file before migrations for Windows compatibility. Prefer an absolute SQLite file URL when deployment working directories vary.

**Do not deploy this unauthenticated single-user MVP directly to the public Internet.** A hosted multi-user product needs authentication/authorization, per-user isolation and quotas, TLS, persistent object storage, database backups, and durable job workers. The current filesystem/SQLite design is unsuitable for ephemeral serverless instances. `after()` jobs and in-memory rate/benchmark locks are not durable across process restarts or shared across instances. Long image sets can exceed host request/job execution limits; use a durable queue before hosted production use. A server restart can interrupt a pending job; existing photos and prior saved revisions remain on disk.

## Known MVP limits

- Handwriting quality and model output remain fallible. Review source evidence, especially equations and corrections.
- Never-captured writing, lecture audio, and exact original timing cannot be recovered.
- Automatic diagram reconstruction and source-region alignment are conservative; the original photograph is the reliable fallback. No advanced geometric analysis or image alignment is implemented.
- Image rotation, ordering, preview, and zoom are supported. Destructive cropping and rich image annotation are not included; crop a copy externally if necessary.
- The mathematical checker is numeric and deliberately limited. It is not a computer algebra system or proof checker.
- Export uses a print-optimized browser view and **Save as PDF**, not a separate server-generated PDF download. Pagination and fonts can vary by browser.
- Provider outputs and processing speed depend on credentials, billing, quota, model access, input quality, and network availability. A real-key smoke test is required to verify your account.
- This local MVP has no sign-in, collaborative editing, OCR-only offline processing, or durable distributed task queue.

## Testing and real-provider smoke test

`npm test` runs deterministic mocked tests. AI tests cover extraction schema shape, source validation, ordering, preservation of an earlier error and correction, arithmetic checks, configured-provider metadata, safe failures, bounded retries, and official SDK request formats. Other suites cover uploads, persistence/editing, replay, comparisons, and export readiness. `npm run typecheck`, `npm run lint`, and `npm run build` are separate checks; see the delivery summary for which commands were actually executed in your environment.

To verify a real provider without confusing it with the sample:

1. Add one real server API key to `.env`; leave the others empty. Choose an accessible vision/structured-output model if overriding the default, then restart `npm run dev`.
2. Create a **new non-demo lesson** and upload 2–3 readable board photographs in chronological order. Include a small visible numerical equality and a later correction if available.
3. Start the configured provider. Confirm extraction and reconstruction stages appear, the run completes or shows a clear provider error, and the saved run records its actual model.
4. Inspect each step's sources and transcription. Check that an earlier captured step remains, a correction preserves its earlier version, and unreadable passages are marked uncertain. A live response is not automatically correct just because the request succeeded.
5. Edit an equation, save, reload, and confirm `USER_EDITED` persistence. Rerun and confirm the prior edited reconstruction is available as a revision.
6. Replay, seek to a source-linked step, then print to PDF and inspect the saved equations and selected photographs.
7. In the Comparison Lab, run the saved common benchmark automatically for each configured provider or paste actual manual responses for the others. Score the real outputs yourself and export the data.

This smoke test incurs provider charges. Automated tests do not require credentials and never claim live API success.
